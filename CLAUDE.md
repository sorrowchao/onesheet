# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

**一表通 (OneSheet)** — Windows desktop GUI (PySide6) for extracting "form (label:value)" data out of Excel / Word (`.docx`) / PDF / CSV files into summary tables, then writing edited summary values back into the source **Excel** files. Single-user, local. Only the `表单（标签:值）` data shape is supported. Word/PDF/CSV are read-only inputs (never written back).

Docs: `README.md` (project overview / quick start), `PRD.md` (requirements), `M1技术方案.md` (technical design — §4 template JSON schema, §5.2 detection rules), `使用说明.txt` (user guide), `CHANGELOG.md` (release notes; current version `app.__version__` = 2.3, shown in the About dialog).

## Architecture

Entry `main.py` → `MainWindow` (`app/main_window.py`), which assembles a 3-panel splitter (FilePanel | PreviewPanel | ConfigPanel) over a bottom QTabWidget with two pages: 汇总结果 (the tabbed `ResultPanel`) and 日志 (`self.log`, read-only `QPlainTextEdit#logView`, hidden until that tab is selected — not a permanent bottom pane), plus a shared progress bar/cancel row, and wires all signals. 试抽当前文件/批量抽取/运行分析/反向写入/导出▾ sit in the QTabWidget's top-right **corner widget**, sharing the tab bar row with 汇总结果/日志; they carry the dynamic property `compact=true` (`theme.py` shrinks their padding so they match the tab height). The vertical splitter default is `setSizes([2000, 1000])` → bottom result area = 1/3 of the window height; the horizontal three-panel splitter default is `setSizes([2500, 4000, 3500])` → 25% : 40% : 35%. (Plain small ratios like `[2, 1]` do NOT work: `setSizes` clamps each entry to the widget's `minimumSizeHint`, skewing the ratio.) The window top is a **menu bar** (文件/模板/数据/视图/帮助 — `_build_menus`), not a flat toolbar; action buttons are **placed next to what they act on**: 导入文件/导入文件夹 live in `FilePanel` (emit `import_files_requested`/`import_folder_requested`), 打开模板/保存模板 live in `ConfigPanel` (emit `open_template_requested`/`save_template_requested`, backed by `btn_open_tpl`/`btn_save_tpl`), and 试抽当前文件/批量抽取/反向写入/导出▾ live in a header row above `ResultPanel`. The same actions also appear in the menu bar (intentional duplication) with shortcuts (F5 抽取, Ctrl+Shift+W 回写, Ctrl+Shift+L 运行校验, Ctrl+O 导入文件, Ctrl+T 模板管理器, etc.). Files/folders can also be dropped onto the window (`MainWindow.dropEvent` / `FilePanel.dropEvent`); `FilePanel.files_dropped` lets the window remember the directory. The UI is skinned to look like VSCode via `app/ui/theme.py` (dark/light QSS, applied to `QApplication`), using rounded cards (8–10px), banded `#sectionHeader` labels and 4px splitters for clear panel separation; QGroupBox titles sit inside the card (42px top padding; 15px bold with a 4px accent left bar) rather than straddling the border, and nested group boxes (e.g. 字段映射 inside 当前结果表配置) use a transparent background with a 13px bold title and a 3px accent left bar. The bold comes from `QGroupBox { font-weight: 700 }` — Qt **ignores** `font-weight`/`font` on `QGroupBox::title` (verified: weight 400 vs 900 render identically), so never put the weight on the `::title` subcontrol; children are unaffected because the global `QWidget` rule resolves their font separately; 视图 menu → 深色/浅色主题 toggles it live and persists the choice (`settings.get_theme`/`set_theme`, default `dark`). On Windows the native title bar follows the theme too: `_set_theme` calls `app/ui/title_bar_win.py:apply_dark_title_bar` (DWM immersive dark mode, attribute 20 then legacy 19; silently no-op on non-Windows/unsupported systems), and `MainWindow.showEvent` reapplies it once the HWND is stable. After a successful attribute change it forces an immediate non-client repaint by sending `WM_NCACTIVATE` (0x0086) twice with wParam 0 then 1 — Windows 10 otherwise only refreshes the title bar on the next maximize/restore, and `RedrawWindow`/`SetWindowPos` do not help (they target the client area). Checkbox ticks are drawn from `app/ui/assets/check.svg` via QSS `image: url(...)` (`theme.check_icon_path()`); the asset is listed in `onesheet.spec` `datas` so the onefile exe can resolve it. Global UI font: `main.py` calls `app/ui/font.py:apply_app_font(app)` **before** constructing `MainWindow`, setting a preferred-family chain (Microsoft YaHei UI → YaHei → Segoe UI → …) at 9.75pt; QSS base text is 13px, and `QPlainTextEdit#logView` (main log + write-back report) uses Consolas. Each panel carries a `#sectionHeader` label (文件管理器/预览/配置). `FilePanel`'s 全选/反选/全不选 all act on the currently **visible** (search-filtered) items; with a keyword, 全选 also unchecks the hidden ones, while 反选 only flips visible ones. Help → 使用说明 opens `使用说明.txt` via `QDesktopServices.openUrl`: source run uses the project root; frozen builds try exe dir, then its parent, then `sys._MEIPASS` (the spec `datas` bundles the file, so a standalone exe still has a copy). Help → 关于 opens `AboutDialog` (`app/ui/about_dialog.py`): app intro plus a 「致谢与联系」 card (icon source from 阿里巴巴矢量图标库 with link, code by 忧凉 & DeepSeek-V4.1-Flash-1017, clickable contact email, infringement notice), using the same `#sectionHeader` + rounded-card design language as the other dialogs.

Core pipeline (`app/core/`), one direction is extract, the other is write-back:

- `reader.read_excel` — reads one Excel file's sheets into `SheetData` (full `grid[r][c]` snapshot + merged-cell `Region`s). Dispatches xlsx/xls by **magic bytes**, not extension; `reader.detect_format(path)` holds that logic (now returns `xlsx|xls|docx|pdf|csv`) and is shared with `document_reader` and `writer`. `EXCEL_FORMATS = ("xlsx", "xls")`; `read_excel` raises `ValueError("不是 Excel 文件…")` for anything else. **docx and xlsx are both ZIP**, so `detect_format` opens the archive with `zipfile` and checks members (`word/document.xml` → docx, `xl/workbook.xml` → xlsx). OLE2 + `.doc` raises an explicit "unsupported old Word" error.
- `csv_reader.read_csv` — one `SheetData` named `CSV` (stable across files so templates can match it): decode `utf-8-sig` → UTF-16 (BOM) → `gb18030`; delimiter via `csv.Sniffer` (`, ; \\t |`, fallback comma); cells stay **strings** (no numeric conversion) so `007` keeps leading zeros; rows padded to a rectangle and trailing all-empty rows/columns trimmed.
- `docx_reader.read_docx` — each table → `表1`, `表2`… (document order); non-empty paragraphs → `正文`, splitting each line on the first `：`/`:`/tab into `[label, value]`. Merged cells are rebuilt from shared `id(cell._tc)` (covers both gridSpan and vMerge) and non-top-left cells are blanked, matching Excel's `MergedCell` behavior.
- `pdf_reader.read_pdf` — text pages use pdfplumber: `extract_tables()` → per-page `第N页-表K`; if no tables, `extract_words()` is clustered into rows (`top` ±3pt) / columns (gaps >12pt) → `第N页-正文` (single-cell rows containing `：`/`:`/tab are split into label/value). Pages without a text layer (after whitespace removal < 30 chars) are **scanned**: render at 150 DPI → JPEG data URL → OpenAI-compatible **vision model** → `{"rows": [[...], ...]}` → `第N页-扫描`. Reuses `ai_scan.default_caller` and the same Key/URL; `pdf_open`/`caller` are injectable; logs to `data/logs/pdf_vision.log` only for the default caller; checks `cancel_cb` per page. **Page stitching**: `_merge_pages` then groups those per-page sheets by the suffix after the last `-` and concatenates each group in page order into ONE sheet named `表K`/`正文`/`扫描` (column count = widest page, right-padded with `None` by `_rows_to_grid`, never truncated). This is essential, not cosmetic: a continuation page often holds only the last 1–2 rows and comes back one column narrower (last column empty), so keeping pages separate split one logical table — AI scan on the last page produced a single mapping, positional `value_col` shifted between pages, and files with different page counts got different row positions. After stitching, the `test/4` forms (2-page and 3-page variants) all yield the same 5-column × 31-row `表1`, so one template works for all.
- `document_reader.read_document` — dispatcher by `detect_format` → `read_excel` / `read_docx` / `read_pdf` / `read_csv`; `is_excel_file` / `partition_excel_files` gate reverse write-back (non-Excel files are skipped and logged).
- `detector.detect_form_pairs_pos` — heuristically finds `(label, label_row, label_col, value_row, value_col)` pairs in a form sheet (1-based).
- `align.align_sheet` — **自动对齐（纯逻辑）**：模板坐标是绝对位置，源文件删掉顶部若干行/列后全部映射会错位。`align_sheet(sheet, fields)` 以模板里的 `label_row/label_col` 为锚点，规范化标签文本（`clean_label` + 全半角统一 + 去空白；`项目名称1` 再退化为 `项目名称`），在 sheet 中索引所有字符串单元格，对每个锚点投票 `(row_delta, col_delta)`（每个锚点最多一票），取票数最高者；平票时取曼哈顿距离最小（`(0,0)` 优先）。返回 `Alignment(row_delta, col_delta, votes, anchor_count, conflict)`，`shifted` 表示非零偏移，`reliable = votes > 0 and not conflict`，`offset` 只在 `reliable` 时返回偏移、否则 `(0,0)`（所有调用方都用 `offset`，不要直接用 `row_delta/col_delta`）。**非零偏移必须有过半锚点支持**（`votes[best] * 2 > len(anchors)`），单个标签偶然出现在别处不能让整表平移；零偏移不要求过半。`conflict = not majority and (moved or len(votes) > 1)`。`source="filename"` 字段不参与。extractor、writer、config_panel 值预览、preview_panel 高亮共用它。
- `extractor.extract_file` — per file: produces `{table_name: ResultTable}` from the template's `output_tables` (one row per file, form mode). Takes an optional `path` used only by `source="filename"` fields: `object_name_from_path` keeps Chinese characters from the file stem (dropping Latin letters/digits/punctuation) and falls back to the parent folder name when the stem has none (e.g. `X企业2024.xlsx` → `企业`, `采购部/2024.xlsx` → `采购部`). ConfigPanel's 添加文件名 button adds such a field (`target="文件名"`, no value position); its 值预览 shows the derived name for the current preview file, and write-back ignores it (no cell position). **自动对齐**：每张 sheet 先 `align_sheet`，所有 `value_row/value_col` 及同类行溢出读取都加上 `(row_delta, col_delta)`；`label_to_val` 文本回退保持不偏移。可选 `notes: list[str]` 收集每个输出表的对齐信息（偏移时「按标签对齐：行 -3，列 +0（2/2 个标签命中）」；有锚点但不可靠时「疑似版式变化，未能可靠对齐…已按模板原位置读取」）。按标签文本回退取值（`label_to_val`）本身按文本查找，不做偏移。<br>`test/3/可瑞汽车/可瑞汽车107-1.xlsx`（顶部删 3 行）用 `xm.json` 抽出的 3 个项目名与其余公司一致；国能/祥瑞为 `(0,0)`。
- `aggregator.aggregate` — merges per-file results by table name: union of columns (first-seen order), trims, drops empty rows, sorts by first data column, then prepends a `序号` sequence column (`SEQ_COLUMN`).
- `exporter` — writes `{name: ResultTable}` to multi-sheet xlsx, or one csv per table (utf-8-sig).
- `validator` — pure-logic data validation (no Qt). `ValidationRule` lives on `OutputTable.validations` (types `required` / `number` / `unique` / `sum`; `VALID_RULE_TYPES` in `models.py`). `validate_table(table, rules)` returns `list[ValidationIssue]` (0-based `row`, `-1` = table-level; empty `column`). Rules: `required` flags empty/whitespace cells; `number` skips empties, flags non-numeric and out-of-range (bounds inclusive, `1e-9` epsilon); `unique` normalizes keys with `models.norm_key` and marks **every** row of a duplicate group (supports composite multi-column keys, ignores all-empty keys); `sum` treats empty addends as 0, missing total as 「合计为空」, compares with `max(tolerance, 1e-9)`. A rule referencing a missing column yields one table-level issue instead of raising. `validate_results(results, template)` looks up each `OutputTable` by name and validates only tables that actually produced results and have rules. `describe_rule(rule)` renders the Chinese label used in the rules dialog and log.
- `formula` — **派生列公式的安全求值**（纯逻辑，无 Qt，2026-11）：`[列名]` 引用先重写成内部变量 `_ref_N`，再 `ast.parse(mode="eval")`，只放行白名单节点（`Expression/BinOp(+-*/%)/UnaryOp(+-)/Constant(int,float)/Call(Name)/Name`；不提供 `**`），函数白名单 `round/abs/int/float/min/max`。`extract_refs` / `syntax_ok` / `validate_formula` / `compile_formula` / `evaluate`；引用为空或非数值、除零、溢出 → 返回 `None`（不抛），整数结果归一 int。**不用 eval/compile**；未知列名/函数/属性/下标/关键字参数一律 `FormulaError`。schema 只做结构校验（`syntax_ok`），列存在性在 `validate()` 里按顺序检查。
- `analysis` — **分析准备引擎**（纯逻辑，无 Qt，2026-11）：`apply_cleanup`（trim → filters → dedupe；去重键为空时取全部列去掉 `序号`，保留首次出现；行有删减且首列是 `序号` 时重排）→ `apply_derived_columns`（顺序编译求值，已有列原位重算、否则追加，非法配置记 note 跳过）→ `build_group_by` / `build_stats`（生成额外结果表，名称 `<基础表>（分组汇总）` / `（描述统计）`，重名加数字后缀）。`apply_analysis(tables, template)` 先按名称正则**丢弃上次生成的表**再重算，保证重复运行不叠加；基础表在前、生成表在后（dict 顺序即页签顺序）；无任何配置时原样返回。`is_empty`/`to_number` 与 validator 共用（在 `models.py`）。数值归一 int，标准差用总体 `statistics.pstdev`。
- `folder_scan.scan_folder` — pure-logic folder import filter (no Qt): groups **input files** (`INPUT_EXTS = EXCEL_EXTS | DOCUMENT_EXTS`, where `DOCUMENT_EXTS = {".docx", ".pdf", ".csv"}`) by **immediate parent directory** (root group first), files are ranked within each group by one of five sorts (mtime newest/oldest, name A→Z, size largest/smallest), optionally truncated by `per_folder_limit`, filtered by inclusive byte size bounds and `re.search(name_pattern, file name)`; files whose name starts with `~$` (Office lock/temp files) are always ignored. `SORT_PATH` preserves the legacy global relative-path order used by `collect_input_files`. `normalize_options` sanitizes persisted options; `FolderScanError` carries zh messages. `app/ui/import_folder_dialog.py` wraps it in a dialog with a debounced live preview (relative paths, `PREVIEW_LIMIT` 200) and `selected_files()` returning the full result; `MainWindow._import_folder` saves the options via settings. Dragging folders onto the window keeps the old no-dialog behavior.
- `writer.write_back` — reverse write (Excel only; `_plan_files`/`_save` reject other formats defensively): matches each summary row to a source file by **composite key** (`key_cols`), then writes back only fields with `value_row`/`value_col` positions into `out_dir` (never overwrites originals). Key values are compared via `_norm_key`. Matching lives in `_plan_files`; `preview_write_back` reuses it to report `file_count`/`cell_count` without writing, and `write_back` saves the planned matches. **自动对齐**：每张源 sheet 同样 `align_sheet`，读取匹配键和写入值都加 `(dr, dc)`；有偏移时若目标坐标越界则跳过该写入，`report["aligned"]` 记录 `(path, dr, dc)`，`report["alignment_warnings"]` 记录有锚点但不可靠的 sheet。`preview_write_back` 返回同样的两个字段，`_confirm_write_back_plan` / `_on_write_back_done` 会把「对齐 N 个」和警告写进确认框/日志。 The result table header's 试抽当前文件 uses `extract_file` + `aggregate` on the current preview file in a `TryExtractDialog` (doesn't touch `self._results`). The completion report is **not** a dialog: `_on_write_back_done` writes per-file results plus one summary line (written / unmatched / errors / unused rows) to the log and status bar.
- `ai_scan.recommend_fields` — **AI path** for generating fields: renders the previewed sheet as text (`build_sheet_text`: one line per row, `行N: 列=值 | 列=值 | …`, only non-empty cells, explicit column numbers) → POSTs to an **OpenAI-compatible chat completions** endpoint (default DeepSeek; `api_url`/`model` configurable, so OpenAI/Qwen/Kimi/local servers work) → parses the JSON reply into `FieldMapping`s. `normalize_api_url` accepts a base URL (`…/v1`) or a full `…/chat/completions` endpoint; on HTTP 400 the caller retries once without `response_format` (some compatible servers lack JSON mode). Pure logic, no Qt; network via stdlib `urllib.request` (**no new dependency** — don't add `requests`). `caller` is injectable for tests; `AiScanError` carries friendly zh messages. The local heuristic (`detector.detect_form_pairs_pos`) is unchanged — AI is only an extra "generate fields" entry.

Templates (`app/template/`): `schema.py` (dict ↔ dataclass + `validate`) and `store.py` (JSON under `data/templates/`, base dir from `app/paths.data_dir()`; `save_path`/`duplicate`/`rename`/`delete` power the template manager; `list_templates` returns `{path, name, mtime}`). The manager dialog (`app/ui/template_manager.py`) is a 3-column table (模板名/最后修改/文件) sorted by mtime descending, auto-selecting the newest row, and offers open/rename/duplicate/delete/refresh; entry points are 模板 → 模板管理器… (Ctrl+T) and the ConfigPanel 管理 button.

ConfigPanel → preview linkage: selecting a row in the field table emits `field_selected(FieldMapping)`, and `PreviewPanel.highlight_field(field, offset)` scrolls to and selects the label/value cells (or finds the label text when the field has no positions). `MainWindow._on_field_selected` computes the offset with `align_sheet` on the current sheet, so the highlight follows a shifted layout; ConfigPanel's 值预览 uses the same offset.

Settings (`app/service/settings.py`): `data/settings.json` holds the AI interface config (API key `deepseek_api_key`, address `ai_api_url`, model `ai_model`, vision model `ai_vision_model`), the theme, the chosen app icon, the window state (`window_state`: width/height/maximized/splitter sizes), the last import directory (`last_import_dir`), and the last folder-import filter options (`folder_import_options`) (base dir from `app/paths.data_dir()`, shared with `store.py`/`ai_scan`). `MainWindow._restore_window_state` applies it at startup and `closeEvent` saves it; import dialogs start in `get_last_import_dir()`. `get_api_key` prefers env `DEEPSEEK_API_KEY` then `OPENAI_API_KEY`, else the file; `get_ai_api_url`/`get_ai_model`/`get_ai_vision_model` prefer env `OPENAI_BASE_URL`/`OPENAI_MODEL`/`OPENAI_VISION_MODEL`, else the file (empty model/vision model means "use the ai_scan default model"; vision falls back to `get_ai_model`); `get_stored_*` ignore env for dialog prefill; missing/corrupt JSON returns `{}` instead of raising. Built-in app icons live in `app/icons/` (`.png/.ico/.svg/.jpg/...`, bundled into the exe; resolved via `app.paths.resource_dir()` = `_MEIPASS` when frozen), and an optional user dir `data/icons/` can override/add icons by name. `available_icons` merges both (user wins on the same stem), sorts numeric names numerically; `resolve_icon_name`/`get_icon` default to `DEFAULT_ICON = "4"` (then the first available when 4 is missing). 视图 → 应用图标 lists them; `MainWindow._set_icon` applies the `QIcon` to both `QApplication` and the window and persists the choice. `main.py:_set_windows_app_id()` calls `SetCurrentProcessExplicitAppUserModelID("OneSheet.Onesheet")` before creating the QApplication so the Win10 taskbar treats the app as its own group and uses its window icon instead of `python.exe`.

Threading (`app/service/worker.py`): `ExtractWorker` / `WriteBackWorker` / `AiScanWorker` are `QThread` subclasses that emit progress/result signals back to the main thread. `ExtractWorker` also emits `file_note(path, note)` for each alignment note from `extract_file(..., notes=...)`; `main_window` logs them as `对齐：<file> — <note>`. `ExtractWorker` and `WriteBackWorker` support cancellation (`cancel()` + `_cancelled`; Extract emits `cancelled(processed, total)` and returns without `done`; WriteBack passes `cancel_cb` into `writer.write_back`, which sets `report["cancelled"]` and keeps already-written files). `MainWindow` re-entry-guards tasks with `_task_running()` and toggles `btn_cancel` via `_start_task`/`_finish_task`/`_cancel_task`.

Results (`app/ui/result_panel.py`): `ResultPanel` hosts one `ResultTableWidget` (QTableWidget subclass) per table. The widget is editable with Excel-like operations: Ctrl+C/Ctrl+V TSV clipboard, Ctrl+Z/Ctrl+Y undo/redo (full-table snapshots, max 100), Delete clear, context menu insert/delete rows, and `_renumber_seq()` keeps the `序号` column ordered. `read_results()` reads edits back and coerces numbers using baseline types captured in `show_results`. **Validation marks**: `apply_validation(issues)` groups issues by table, maps `column` name → header index, and paints cell background/foreground (`set_error_style(bg, fg)`, colors from `theme.palette()[error_bg/error_text]`) with the message as tooltip; unknown columns / other tables are ignored. Marks are stored in `_marks[(row,col)]`, cleared automatically when the cell is edited/pasted/cleared or on row insert/delete, and reapplied by any later `setItem`. All visual mark operations run under the `_restoring` guard because `setBackground` emits `itemChanged` (whose handler pops marks) — without it you get "dictionary changed size during iteration".

Validation rules dialog (`app/ui/validation_rules_dialog.py`): `ValidationRulesDialog(output_table)` edits a copy of `OutputTable.validations` in a 2-column table (类型/规则 via `describe_rule`), with 添加/编辑/删除; `RuleEditDialog(columns, rule)` shows dynamic widgets per type (single column for required/number, checkable multi-column list for unique/sum, target + tolerance for sum, min/max for number) and rejects empty column lists / invalid min-max via `QMessageBox.warning`. ConfigPanel's 结果表 button row has `btn_rules` ("校验规则…") emitting `validation_rules_requested`; it also exposes `current_output_table()` and `set_current_validations(rules)` (defensive copies), and `_clone_table` copies `validations`. `MainWindow` connects the signal to `_edit_validation_rules`, runs `_run_validation` automatically in `_on_extract_done` and via 数据 → 运行校验 (Ctrl+Shift+L), and gates `_run_write_back` with `_confirm_validation_issues` (warns with the first 10 issues, user may continue). Rules are persisted in template JSON as an optional `validations` array (`schema._validate_rule` rejects bad types/empty columns/sum without target/min>max); legacy JSON without it loads with `[]`.

Analysis prep dialog (`app/ui/analysis_prep_dialog.py`): `AnalysisPrepDialog(output_table)` has four tabs (派生列 / 清洗·去重 / 分组汇总 / 描述统计) editing clones of `OutputTable.derived_columns` / `cleanup` / `group_by` / `stats`; sub-dialogs `DerivedColumnEditDialog` (validates non-empty target, no clash with export columns, `validate_formula`), `FilterEditDialog` (value input hidden for `not_empty`/`empty`), `AggregateEditDialog`. Available columns = field targets minus `序号` plus configured derived targets, refreshed after derived changes while preserving check state. ConfigPanel's result-table button row has `btn_analysis` ("分析准备…") emitting `analysis_requested`; it also exposes `set_current_analysis(derived, cleanup, group_by, stats)` (defensive copies) and `_clone_table` deep-copies all four fields (otherwise opening a template drops the analysis config). `MainWindow._edit_analysis` opens the dialog; `_run_analysis` is **manual only** (corner button 运行分析 / 数据 → 运行分析, Ctrl+Shift+A — NOT hooked to `_on_extract_done` or 试抽): reads `read_results()`, runs `apply_analysis`, replaces `self._results` and the result tabs, logs each note as `分析：…`, then re-runs validation (`_run_validation`) because dedupe/filter changed row numbers. Generated group/stats tables are exportable but must not reach write-back: `_run_write_back` filters `edited` through the static `_base_result_tables(edited, template)` (keeps only names of `template.output_tables`). Schema persists the four keys as optional arrays/objects; legacy JSON loads with defaults (`schema._validate_analysis` checks derived refs in order, filter ops, agg funcs, stat metrics).

## Conventions

- `Region`, and `FieldMapping` `value_row/value_col/label_row/label_col`, are **1-based and inclusive**; `bottom/right = -1` means "to the end". `SheetData.grid` is 0-based.
- `FieldMapping.source` is `kv` (cell/label lookup) or `filename` (derived from the file path; keep Chinese only, fall back to the parent folder). A `kv` field without `value_row/value_col` resolves the value by matching `key` against scanned `label:value` pairs. `filename` fields have no cell positions, so they are never written back and never offered as write-back match columns.
- Output column names come from `FieldMapping.target`. Duplicate targets are auto-renamed by `models.dedupe_targets` (first keeps its name, later ones get `2`, `3`… — only `target` changes, `key` stays). It is **family-aware and name-agnostic**: any trailing-digit name (`项目名称1`, `股东1`, `指标10`, `A1`) forms a family; when `XX1`/`XX2` already exist, a newly added bare `XX` (or another `XX1`) continues at `XX3` instead of staying bare / becoming `XX12`. The family's number style is preserved (zero padding `股东01/02` → `股东03`, full-width `费用１/２` → `费用３`); an explicitly typed free number (`XX3`) is kept as-is; all-digit names (`2024`) still duplicate as `20242`.
- `ResultTable` is the universal in-memory table shape (`columns` + `rows`).
- `SEQ_COLUMN` (`序号`) is reserved as the first column and is excluded from write-back matching.

## Gotchas

- **Format detection**: a WPS-saved `.xls` (OLE2) may be named `.xlsx`. Read magic bytes first (`PK\x03\x04` → openpyxl, `\xd0\xcf\x11\xe0\xa1\xb1\x1a\xe1` → xlrd), fall back to extension only if unrecognized.
- **Data dir when frozen**: `app/paths.py` resolves it for `store.py`/`settings.py`/`ai_scan.py`. The exe's own `data/templates/` wins if it holds templates; otherwise a parent `data/templates/` with templates is used (so running `dist/onesheet.exe` sees the project's `data/` instead of an empty `dist/data/`); with none it falls back to the exe directory. Read-only bundled assets use `resource_dir()` instead (`_MEIPASS` when frozen, project root in source) — e.g. built-in icons in `app/icons/`. Don't reintroduce per-module `sys.frozen` branches. `main.py` calls `paths.ensure_data_dirs()` before constructing `MainWindow`, so first launch creates `data/` plus `data/{templates,logs,icons}` (best-effort: `OSError` is ignored so a read-only install still starts).
- **Edited results must be read back**: `ResultPanel.read_results()` re-reads the editable QTableWidget and coerces cells back to int/float using the baseline types; `main_window._run_write_back` uses this, not the stale `self._results`.
- **Duplicate value positions**: `models.duplicate_value_positions()` warns when several fields in one output table share the same `(value_row, value_col)`. `MainWindow._confirm_duplicate_positions()` is called by both `_save_template` and `_run_extract`; the user may still proceed.
- **Template save path**: `_save_template` opens a save dialog defaulting to `data/templates/<name>.json` and MUST call `template_store.save_path(tpl, path)` — `save()` ignores the dialog path and writes to the template dir.
- **QComboBox popup**: the popup is a QListView. On real Windows, `selection-color` is applied to the current item but the selection background is not drawn unless an explicit `QComboBox QAbstractItemView::item:selected { background-color; color; }` rule exists — without it the current item is white-on-white in the light theme.
- **Key normalization**: write-back matching uses `norm_key` (lives in `models.py`, re-exported as `writer._norm_key`) so `"1,234"`, `1234`, `1234.0` compare equal while `"007"` keeps its leading zeros. The `unique` validation rule shares the same function.
- **Automatic alignment is per sheet, not per file**: `align_sheet` votes on whole-sheet `(dr, dc)` using the template's label anchors; it corrects uniformly deleted/inserted top rows or left columns, not arbitrary row/column removal in the middle. A **non-zero** offset additionally requires a strict majority of anchors (`votes * 2 > anchor_count`); when no anchor matches, or a shift lacks that majority, `Alignment.offset` is `(0,0)`, a warning note is emitted (extract) / recorded in `alignment_warnings` (write-back), and the template's original positions are used. This keeps normal files safe: verified across `test/1`–`test/4` with `11.json` (10/10 zero), `99.json`, `xm.json` (2/2 zero except 可瑞107-1 `(-3,0)`); `99.json` matching a foreign file with only 1/8 anchors used to shift by +2 and now stays at zero. Labels must be ≥`MIN_ANCHOR_LEN` (2) characters after normalization; `项目名称1` falls back to `项目名称`.
- **config_panel `_loading`**: rebuilding a form under `_loading=True` suppresses `currentRowChanged`; `_rebuild_table_list` must call `_populate_form` explicitly or the first table's form ends up empty.
- **Field-map table selection**: `_FieldsTable` uses `ExtendedSelection` so `删除选中` (`_del_field_row`) can delete several selected rows at once (falls back to the current row when nothing is selected); `_selected_rows()` reads `selectionModel().selectedRows()`. `全选`/`反选`/`全不选` (`_select_all_form`/`_invert_checked`/`_clear_form`) only change check states; `清空` (`_clear_all_form`) deletes every field behind a `QMessageBox` confirm. Row drag-reorder still acts on `currentRow()` only. The table height is capped at 360px (min 240). `_FieldsTable.wheelEvent` scrolls the table while it can, and when the wheel points past the table's top/bottom (or the table needs no scrolling) it calls `event.ignore()` so the event reaches ConfigPanel's outer `QScrollArea` (`self.scroll`) — standard nested-scroll chaining, no dead zone over the mapping area.
- **detector**: do not add a `MIN_HEADER_CELLS` threshold — it kills single-cell headers (e.g. `甲`), which the M1 spec does not require.
- **Persisted templates in-repo**: `data/templates/*.json` (e.g. `11.json`, `xm.json`) are real user templates written by `store.py`; editing them changes behavior at runtime.
- **AI scan**: `ai_scan` sends only the **current previewed sheet** (truncated to `max_rows`/`max_cols`, defaults 200×40 — a real statistics form runs to ~91 rows, so a smaller cap truncates real fields) and reads config from env first, else `data/settings.json` (plaintext — accepted for a single-user local tool). Env vars: `DEEPSEEK_API_KEY`/`OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`. `main_window._on_ai_scan_form` guards reentry via `self._ai_worker` and prompts with `ApiKeyDialog` only when no key is configured. `ApiKeyDialog` (menu 数据 → “AI 接口设置（OpenAI 兼容）…”, `_edit_api_key`) edits key + API address + model: key masked with a 显示明文 toggle, stored env-var overrides are noted; submitting empty clears each item. `settings.get_stored_api_key()` reads only the file; `settings.env_api_key()` reads only the env (same pattern for URL/model).
- **AI scan prompt covers three layouts** (it must **not** tell the model to ignore headers — the old prompt did, killing that table form): (1) adjacent `label:value` (value = nearest non-empty cell right/below); (2) **横向表格** — header row holds column labels, data rows below, each `header × data-row` a field numbered `项目名称1/2/3…`, sharing the header cell as `label_row/label_col`; (3) **纵向指标表** (e.g. a `指标名称/计量单位/代码/数量` layout) — `指标名称/计量单位/代码/数量` columns, label in col 1, value in the `数量` column (NOT the `计量单位`/`代码` columns in between). `build_sheet_text` gives every cell its **explicit column number** (`列=值`) so the model never counts tabs — sparse grids made it drift (the model returned the empty col 7 instead of the `数量` col 10, and the empty-value filter then dropped everything). It also collapses in-cell newlines/tabs to single spaces, or embedded `\n` (e.g. `项目人员\n（人）`) adds phantom lines and misaligns row numbers.
- **AI scan filters empty values**: `parse_pairs` drops any field whose resolved value cell is empty/whitespace (`_cell_is_empty`) — so label-only columns (e.g. an empty optional column, or an empty trailing data row) never make it into the field table. The prompt also asks the model to skip them, but the filter is the reliable guarantee.
- **AI scan logs every real call** to `data/logs/ai_scan.log` (under `app.paths.data_dir()`, appended): parsed fields + raw model reply. Only written when `caller is default_caller` (injected/test callers skip it). Use it to iterate on the prompt — the log shows exactly what the model returned vs. what survived parsing/filtering. Known failure modes seen in the log and counter-instructed in the prompt: (a) form-admin boilerplate (form ID, issuing agency, document number, expiry date) — told to ignore, keep only entity identifiers like organization code / unit name; (b) **off-by-one `value_col`** when the value sits past an empty column (caught by the empty filter, but the prompt now says "列号必须数准"); (c) unit annotations glued to labels (`项目人员 （人）1`) — prompt now asks for `项目人员（人）1` (no stray space, number last).
