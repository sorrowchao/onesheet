一表通（OneSheet）技术说明
（供论文写作参考，版本 v2.3，2026-11-16）

一、软件定位与作用
------------------------------------------
一表通是面向 Windows 的单机桌面数据处理工具，解决基层业务中大量存在的
“表格数据归集”问题：同一套统计报表被拆成几十上百个 Excel、Word、PDF、
CSV 文件下发，回收后需人工逐份打开、复制字段、粘贴成汇总表；修改后还要
逐一写回源文件。工作重复、易错、耗时，且各来源版式常有细微差异。

本软件把流程抽象为“模板驱动的表单（标签:值）抽取—汇总—校验—分析—
反向写入”闭环：用户对一份样表框选或自动识别一次字段，生成可复用模板；
批量导入同类文件即可抽成汇总表；汇总表可像 Excel 一样编辑，并执行校验、
派生列、去重分组与描述统计；确认后按主键回填各源 Excel（另存，不覆盖
原件）并保留原格式。Word、PDF、CSV 只读，可与 Excel 混合导入、混合抽取。

数据形态限定为“表单（标签:值）”，含相邻标签-值对、横向表格与纵向指标表。
系统不追求任意表格的通用抽取，而在此约束下追求高准确率、可解释性与
可复核性。

二、总体架构
------------------------------------------
系统分五层：
1) 核心层 app/core：纯逻辑、不依赖 Qt，负责格式识别、多格式读取、表单
   检测、锚点对齐、抽取、汇总、导出、校验、公式求值、分析再加工与回写。
2) 模板层 app/template：数据模型、JSON 序列化/校验与模板存取。
3) 服务层 app/service：设置持久化与 QThread 后台工作器，耗时任务移出
   UI 线程并支持取消。
4) 界面层 app/ui：PySide6 三栏主窗口、结果区、日志区与对话框，统一
   VSCode 风格深浅主题。
5) 入口 main.py：初始化数据目录、全局字体与 Windows 应用标识并装配窗口。

统一数据模型是关键：SheetData 是矩形快照与合并区域；FieldMapping 描述
标签位置、取值位置、输出列名、类型与主键，位置统一 1 基；ResultTable
以“列名+行”贯穿抽取、汇总、校验、分析与导出；ExtractTemplate 由输出表
组成，每张表绑定 sheet 关键字、字段及校验、派生、清洗、分组、统计配置。
所有格式最终都归一化为 SheetData，下游环节对文件格式无感，这是“多格式
统一”的基础。

三、核心机制
------------------------------------------
1. 魔数识别与多格式归一化
   文件格式不依赖扩展名，而读文件头：ZIP 再检查成员，含 word/document.xml
   判 docx，含 xl/workbook.xml 判 xlsx；OLE2 判 xls，.doc 明确拒绝。这样
   WPS 保存的旧 .xls 被改名成 .xlsx 也能选对解析器。读取层将四种输入统一
   为 SheetData：Excel 保留全表快照与合并区域；Word 每个表格命名“表1、
   表2…”，段落汇入“正文”并按首个冒号或制表符拆标签/值；CSV 依次以
   utf-8-sig、UTF-16、gb18030 解码，Sniffer 识别分隔符，单元格保持字符串
   以保留“007”前导零；PDF 文字页优先抽表，无表时按文字坐标聚类重建行列，
   扫描页渲染为图片交视觉模型。PDF 跨页同类表格按页序拼接、以最宽页补空
   列，使 2 页与 3 页文件的行列结构一致。

2. 模板驱动的字段映射与检测
   字段生成有三条路径：启发式扫描、AI 扫描、手动配对。启发式在行列间
   寻找“标签:值”相邻结构，不设表头单元格阈值，兼容单字表头；AI 把
   sheet 渲染为“行N: 列=值”的显式坐标文本，调用 OpenAI 兼容接口返回
   JSON，避免模型数制表符导致列号漂移，并在解析层丢弃空值字段。结果均可
   勾选、编辑、拖动排序；重名自动加数字后缀并保留编号风格。字段顺序只
   决定导出列序，不影响抽取与回写，因为二者按列名和位置匹配。

3. 标签锚点自动对齐（核心算法）
   模板记录创建时该表的绝对坐标，源文件删掉顶部行或左侧列会整体错位。
   align_sheet 以模板标签位置与文本为锚点：标签先规范化（去冒号、空白、
   全半角统一；“项目名称1”退化为“项目名称”），再在当前表索引全部字符串
   单元格，为每个锚点生成候选偏移 (行差, 列差)；每锚点对同一偏移最多一票，
   取最高票，平票取曼哈顿距离最小者（零偏移优先）。非零偏移须获过半锚点
   支持；证据不足或冲突时不采用偏移，仍按原位置读取，并在日志、试抽与
   回写确认中提示“疑似版式变化”。该算法用于抽取、试抽、预览高亮、值预览
   与回写，使一份模板可适配删行改版的同类文件。

4. 批量抽取、同类行堆叠与汇总
   每个文件按模板输出一行；横向表格中同一取值列、标签行的多个字段视为
   同类行，数据超出模板范围时继续向下读同列，遇空停止，以“序号. 值”换行
   堆叠到组内最后字段，避免漏数。多文件结果按表名合并：列取并集、去空行、
   按首个数据列排序，并在最前插入“序号”。结果表支持单元格编辑、TSV 复制
   粘贴、撤销/重做、增删行与序号重排；编辑值会被回读为结构化数据，供
   校验、分析与回写使用。

5. 数据校验（2026-11 新增）
   校验规则随模板持久化，类型包括必填、数值与范围、唯一性、合计。必填
   识别空白或仅空白；数值跳过空值，按闭区间与 1e-9 容差判界；唯一性用
   归一化键处理数值等价与“007”前导零，支持多列复合键，重复组所有行都
   标出，全空键忽略；合计把空分项按 0 计，缺总计报“合计为空”，以绝对值
   与容差比较。规则引用不存在的列只生成表级问题而不抛异常；结果分 0 基
   行级与 -1 表级。结果表直接给问题单元格涂色并附提示，编辑、粘贴、增删
   行后标记失效；抽取后自动校验，回写前如有问题弹窗列出前十条，由用户
   决定是否继续。

6. 派生列与安全公式求值（2026-11 新增）
   派生列形如“[单价] * [数量] * (1 - [折扣])”，结果写入新列或覆盖已有列。
   为防脚本注入，系统不用 eval/compile 执行原文，而是将 [列名] 重写为内部
   变量，用 ast 解析并只放行白名单：加减乘除取余、正负号、数字常量、变量
   引用及 round/abs/int/float/min/max；乘方、属性、下标、关键字参数一律
   报错。引用为空、非数值、除零、溢出时返回空值而不中断流程，整数结果
   归一为整型。模板保存时只做语法校验，列名存在性在执行时按顺序检查，
   因此前一派生列可作为后一列输入。

7. 分析准备（2026-11 新增）
   分析准备把汇总表加工为可分析的明细或统计表，配置随模板保存、由用户
   手动触发，避免抽取后自动改表。顺序固定：先清洗，再派生，最后生成
   统计表。清洗含去首尾空白、按条件过滤、按列去重；去重键为空时默认取
   除“序号”外全部列，保留首次出现，删行且首列为“序号”时自动重排。派生
   列按配置顺序逐条编译求值，已有列原地重算，否则追加，非法配置记日志
   并跳过。分组汇总按一或多个维度列聚合指标（求和、平均、计数、最大、
   最小等）；描述统计输出样本数、均值、中位数、总体标准差等。生成表命名
   为“基础表（分组汇总）”“基础表（描述统计）”，重名加数字后缀；重复运行
   先按名称规律删除上次生成表再重算，保证不叠加。生成表位于基础表之后，
   可导出，但回写前会被过滤，避免统计行写回源文件。

8. 反向写入与格式保留
   反向写入仅针对 Excel。系统按所选匹配字段（可多列复合键）读取分表键值，
   在汇总表查找“全部相同”的行，把该行值写回目标单元格并另存到输出目录。
   键值经归一化，千分位、整数与浮点写法等价，同时保留“007”前导零。写入
   坐标同样经过锚点对齐，越界跳过并记录；合并单元格只能写左上角，系统
   自动重定向；xlsx 复制原对齐后仅改水平居中，xls 用 XLWTWriter 取得原始
   样式再写入，保留字体、边框。写盘前“预演”只读匹配不落盘，报告文件数、
   单元格数、未匹配数、错误数与对齐文件数；过程可取消，已写文件保留。

9. 模板、设置与并发
   模板保存字段、输出表、主键、校验、派生、清洗、分组与统计配置，支持
   打开、另存及管理器中重命名/复制/删除。设置保存 AI Key、地址、模型、
   主题、图标、窗口状态、上次导入目录与筛选选项；Key 优先读环境变量。
   批量抽取、回写、AI 扫描与 PDF 预览均在 QThread 中运行，以信号回传进度
   与结果，主窗口做重入保护并提供取消；核心算法保持纯逻辑，可独立测试。

四、技术亮点（可用于论文总结）
------------------------------------------
1. “模板+锚点投票”的轻量自适应：不依赖机器学习，仅用标签文本投票校正
   整表平移，以“过半支持+冲突检测”换取安全性；无法可靠判断时显式降级
   提示而非静默错读，兼顾自适应、鲁棒性与可解释性。
2. 多格式统一抽象：四种输入归一为 SheetData 与 Region，模板、抽取、汇总、
   校验、分析只实现一次；新增格式仅需增加读取器。
3. 规则与大模型互补：规则负责稳定、零成本、可解释的常规字段；大模型
   覆盖版式多样的表单，并用“显式列号文本化”“空值过滤”“真实调用日志”
   抑制幻觉与坐标漂移，结果均可人工复核。
4. 端到端数据质量闭环：在抽取—汇总—编辑—回写之外加入可配置校验、安全
   派生列与幂等的分析再加工，问题在导出和回写前暴露；回写保留原格式、
   永不覆盖原件，配合预演、逐文件日志与取消机制降低误操作风险。
5. 安全的可编程扩展：派生列以 AST 白名单解释执行，拒绝任意代码与危险
   语法，让业务人员获得类公式灵活性，同时保持桌面软件的边界安全。
6. 工程可维护性与体验：核心层无 UI 依赖、外部依赖可注入，542 个单元测试
   覆盖算法、模板、设置、UI 与读取；VSCode 风格深浅主题，Windows 原生
   标题栏随主题切换并以 WM_NCACTIVATE 立即重绘；三栏默认 25%/40%/35%，
   配置区按“模板—当前结果表配置—结果表”组织，分组标题置于卡片内并加粗；
   单文件 exe，首次运行自动建数据目录，兼顾部署与迁移。

五、局限与可改进方向（论文中可作讨论）
------------------------------------------
· 自动对齐只校正整表统一的行/列平移，不支持中间任意删行或结构重排；
· 数据形态限定为“标签:值”表单，不适用于无标签自由表格；
· 校验为静态单表规则，缺少跨表关联、正则与自定义表达式；
· 派生列不支持条件分支、文本函数与跨表引用；
· AI 扫描依赖外部接口与网络，有费用、延迟与结果波动，需人工复核；
· PDF 扫描页识别受渲染分辨率与视觉模型能力影响；
· 回写仅支持 Excel，Word/PDF/CSV 只读；API Key 明文存储，仅适合单用户
  本地环境。
后续可考虑：版式局部对齐、更多格式、离线小模型、增量抽取、校验规则
模板库与审计日志。

六、可引用的量化信息
------------------------------------------
· 版本：v2.3（2026-11-16），新增数据校验、派生列与分析准备；
· 平台：Windows 10/11；实现：Python 3.14 + PySide6 6.11；
· 单元测试：542 个，覆盖核心算法、模板、设置、UI 与文档读取；
· 打包：PyInstaller 单文件 onesheet.exe，约 52–54 MB，无控制台、无外部
  运行时；
· 依赖：openpyxl、xlrd/xlwt/xlutils、python-docx、pdfplumber、Pillow 等；
· 实测：顶部删 3 行的文件自动识别 (-3,0) 并正确抽取，未改版文件为 (0,0)；
  AI 扫描在 200 行×40 列内稳定识别三类版式；2 页与 3 页同类 PDF 均拼接为
  5 列×31 行，共用一份模板。
